1. Qu’est-ce que le Machine Learning ? Sa place dans l’écosystème de l’IA

1.1. De l’Intelligence Artificielle au Machine Learning

L’Intelligence Artificielle (IA) est le champ scientifique le plus large : il regroupe l’ensemble des théories et techniques mises en œuvre pour concevoir des machines capables de simuler des comportements associés à l’intelligence humaine.

Historiquement, les premiers systèmes d’IA reposaient sur des systèmes experts : des ensembles de règles logiques (SI ... ALORS ...) écrites explicitement par des humains. Ils fonctionnaient bien dans des domaines circonscrits, mais s’avéraient extrêmement coûteux à maintenir et incapables de s’adapter à des situations non anticipées.

Le Machine Learning (ML) constitue une rupture : plutôt que de coder explicitement les règles de décision, on conçoit des algorithmes capables d’extraire eux-mêmes ces règles à partir de données d’exemples.

Le Deep Learning (Apprentissage Profond, DL) est un sous-domaine du ML qui repose sur des réseaux de neurones artificiels comportant de nombreuses couches, performants sur des données non structurées (images, son, texte).

AstuceÀ retenir

Tout algorithme de Deep Learning est un algorithme de Machine Learning, et tout algorithme de Machine Learning appartient au champ de l’IA — mais la réciproque est fausse (ex: un algorithme de recherche aux échecs est de l’IA sans être du ML).

2. Programmation classique vs. approche Data-Driven

2.1. Le paradigme classique

Dans le paradigme classique (déductif), le développeur déduit un ensemble de règles explicites, puis les traduit en code. Le programme prend des données en entrée et produit des résultats en appliquant mécaniquement ces règles. Idéal si les règles métier sont stables et peu nombreuses (ex: calcul d’un impôt).

2.2. Le paradigme Data-Driven

Le Machine Learning inverse la logique : on fournit au système des données et les résultats attendus. L’algorithme analyse les régularités statistiques pour produire un modèle (un programme appris automatiquement), capable de généraliser à de nouvelles données.

Critère Programmation classique Machine Learning
Fourni par l’humain Règles + Données Données + Résultats attendus (exemples)
Produit par le système Résultats Un modèle (règles apprises)
Adaptation Faible (réécriture du code) Élevée (réentraînement)
Interprétabilité Totale Variable selon le modèle

3. Le cycle de vie d’un projet de Machine Learning

Entraîner un modèle ne représente qu’une fraction du travail réel. Un projet ML se décompose en sept étapes itératives (Géron 2022) :

  1. Cadrage du problème métier : Traduire un besoin en problème ML via la grille (T, P, E).
  2. Collecte des données : Rassembler un jeu de données représentatif.
  3. Préparation et nettoyage : Étape la plus chronophage (60-80 % du temps). Traitement des valeurs manquantes, encodage, création de variables (feature engineering).
  4. Modélisation : Choix des algorithmes et entraînement sur les données pour minimiser une erreur.
  5. Évaluation : Mesurer objectivement la performance sur des données jamais vues (test).
  6. Déploiement : Intégrer le modèle dans un système opérationnel (API).
  7. Monitoring : Surveiller les performances pour détecter la dérive des données (data drift).

4.2. Environnements de développement : Exploration vs Production

Il est crucial de distinguer la phase d’exploration (prototypage) de la phase de production (déploiement).

Outils d’exploration :

  • JupyterLab : Interface basée sur des notebooks (cellules de texte/code). Parfait pour l’exploration, l’affichage de graphiques et les travaux pratiques locaux.
  • Google Colab : Notebooks dans le cloud sans installation locale. Idéal pour partager du code ou accéder à des ressources ponctuelles, mais éphémère.

Outils de production :

  • Visual Studio Code (VS Code) : Éditeur généraliste robuste. Indispensable pour restructurer le code des notebooks en scripts modulaires orientés objet, gérer Git, et préparer le déploiement.

4.3. Gestion de projet avec uv

uv : Outil moderne de gestion des environnements et dépendances Python. Il garantit la reproductibilité en déclarant les bibliothèques dans pyproject.toml et en fixant les versions via uv.lock.

uv init
uv add numpy pandas scikit-learn jupyterlab
uv run jupyter lab
